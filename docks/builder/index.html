Etapa 04 · opcional

Slots de itens

Define o inventário por item_slots. Com x/y, o layout padrão respeita a posição; sem posição, usa a grade automática.

Pendente

item_slots

Sem item_slots; o inventário usa inventory_rows.

No layout padrão, slots com x/y válidos mantêm a posição e os demais entram na grade automática de 18 px. Em GUI customizada, slots sem posição ficam apenas para automação. O filter aceita item ou tag; sem filtro, o slot aceita qualquer item. Slots output não usam filtro.

Vazio libera a capability em qualquer bloco formado. Use [] para não expor nenhum bloco. Separe vários seletores por vírgula ou espaço.

Etapa 07 · opcional

GUI e elementos

Personaliza o layout da GUI. Sem uma GUI customizada, o loader usa 176x166 e o inventário do jogador.

Pendente

gui

Sem GUI customizada; o loader usa o layout fallback 176x166.

Layout visual arraste para posicionar

Arraste energia, fluidos, progresso, entidade e demais elementos para ajustar x/y. Os campos numéricos continuam valendo para largura, altura e demais propriedades.

Novos elementos começam com o layout do spawner: título em 8,4, texto em 8,75, inventário em 8,84, barras em 158/148/138,10 com 8x64 e entidade em 96,18 com 36x36. Slots começam em 8,16 e avançam 18 px, com 9 por linha.

Elementos opcional

Uma GUI customizada exige exatamente um player_inventory. item_slots só é obrigatório quando houver elementos slot ou posições x/y; sem slots de item, a GUI pode ter só barras. Barras precisam apontar para a energia ou o tanque existente; progress_bar, arrow e entity só valem em máquinas type=recipe. entity mostra as entidades de inputs/outputs da receita, usa x/y/width/height e exige width/height múltiplos de 18 (mínimo 18), com paginação quando não couberem. Elementos slot usam a referência de item_slots; slots com x/y não podem ser misturados com eles.

Etapa 08 · opcional

Receitas data-driven

Crie os arquivos de receita em data/<namespace>/recipe/. O tipo é fixo e o builder preenche definition automaticamente.

Opcional
Esta definição é storage; receitas não serão processadas por ela. Use uma máquina type=recipe.

Receitas

Nenhuma receita adicionada.

Nenhuma receita. Cada receita vira um arquivo separado. Inputs e outputs aceitam item, fluido, entidade e energia; outputs de item/fluido tem chance individual. Saidas de item exigem slots output, fluidos exigem tanque e entidades usam um seletor de spawn opcional (sem seletor, surgem dentro da area do multibloco).
inputs: lista tipada com item, fluid, entity e energy. Itens usam ingredient e count; fluidos usam ingredient e amount; entidades usam id e spawn opcional (sem seletor, a entidade de saída surge dentro da área do multibloco); energia usa amount. outputs: cada entrada aceita chance de 0 a 1 (default 1) e itens podem ter components. Cole o JSON do /inmb hand no id/tag para separar os campos automaticamente. O builder valida slots, tanques e capacidade de energia e limita a soma dos outputs. Toda receita usa type: infinity_nexus_multiblock:multiblock e recebe definition com o id desta maquina. O JEI mostra multiplos outputs e a chance de cada um.
Gerar JSON no jogo. Use /inmb hand para gerar o input de ingredients e o objeto de output. O input não serve como output e vice-versa; no builder, cole o input no id/tag do ingrediente e o output no id da saída para separar os campos automaticamente. /inmb look envia o ID puro, o matcher completo e o state separado. No campo Bloco dos matchers, cole o ID puro ou o matcher completo: o builder separa bloco e propriedades automaticamente. As linhas no chat são clicáveis e copiam o texto. O alias /infinity_nexus_multiblock faz o mesmo.
